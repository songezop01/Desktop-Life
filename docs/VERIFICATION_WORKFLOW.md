# Verification workflow

Policy updated by the human on 2026-10-08: same-minor fixes and feature updates use **Standard** (including the ten-minute short test), without an automatic long soak. Cross-minor releases such as 0.11 to 0.12 may use **Full**. Explicit stop/skip instructions take precedence; retain the real result and never label an incomplete soak PASS. The 0.11-specific Full gate below documents this already completed cross-minor release, not a requirement to repeat Full for every 0.11.x change.

Use `scripts/verify.ps1 -Mode Quick|Standard|Full`. Quick builds Release and runs all unit tests, including save compatibility and character capabilities. Standard adds isolated WPF smoke and ten minutes of stress. Full adds at least 7200 real seconds of native WPF soak (`-SoakSeconds 14400` or `28800` for longer runs).

Standard and Full launch an independent Windows process and return. An ordinary request to start verification can return after launch; when the user explicitly asks to continue through verification and installation, follow the independent run to completion with bounded status checks. Do not create an unsolicited automation or upload telemetry. The running real pet profile is never used by smoke/stress.

When the user asks to check tests/results, first read `artifacts/verification/latest/verification-summary.md`. Only read its JSON counterpart if machine-readable detail is needed. Read a specific `failures/` package only when referenced by the summary. Do not load raw telemetry or hours of logs by default. No private desktop screenshots, keyboard capture, or desktop contents belong in failure packages.

Each run keeps an immutable run directory containing raw logs and summaries. A process lock prevents overlapping verification. The fixed latest summary records RUNNING until the worker finishes. A terminated worker may leave RUNNING: compare manifest PID and start time before inferring completion. Never infer PASS from an absent report.

Quick currently covers identity, longitudinal and Dual Presence model scenarios. Standard adds isolated WPF smoke and ten minutes of stress; Full adds the native soak. A completed process or passing build is not full V0.8.1 acceptance until the requested stage is marked PASS. Long tests are not evidence of absence of memory leaks.

For 0.10.1 installation, the matching source inventory must have Full PASS. Geometry-change recoveries must reconcile every attempted recovery with an actual grounded escape and no timeouts. Their duration is active visible simulation time: hiding, pausing, editing and holding pause safety movement; resuming must finish it before ordinary activities. Such a pause never counts as a completed recovery. Resource thresholds and raw failures remain reported.

For 0.11 installation, use `scripts/upgrade-011.ps1 -VerificationDirectory <matching Full run>`. The gate checks the retained evidence, the source inventory captured before testing, and the tested application/core binary hashes. All stages must pass, including native 1/2/3-floor checks on each connected monitor, 600 real seconds of short stress and at least 7200 real seconds of soak with all three residents and three floors. Short-stress analysis runs before the soak; a failed or incomplete navigation/resource result stops the later workload. Approach timeouts, unexpected navigation recovery attempts, house route failures and recovery timeouts block installation even when a later fallback escapes.

Source and tested build files must remain unchanged until Full finishes. A correction cancels the current run and requires a new complete run; `CANCELLED`, stale `RUNNING`, Quick and Standard reports cannot authorize 0.11 installation. The published standalone executable gets its own isolated house/WPF checks before safe shutdown and profile backup. Native installation verification then compares the schema6 backup to the schema7 saved profile, preserves all three identities/history and furniture IDs, and checks the actual installed version, checksum and desktop/Start shortcuts. Physical spacedesk phone disconnect, rotation and hardware sleep remain separate from display-inventory injection and connected-monitor DPI checks.
