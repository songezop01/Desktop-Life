## 1. 版本目標與順序

讓使用者透過房間中的食物、工具與玩具照顧角色；角色會回應，也會依需求生活。先修操作失效與診斷閃退，再建立能共用的互動、接觸與動畫機制，最後擴充料理與美術。

1. **P0 可用性**：診斷頁安全開啟；操作不再無聲消失；互動效果與實際演出一致。
2. **P1 日常循環**：實體餵食、靠近摸頭、拖梳子、真實玩球、自主睡眠；移除照顧右鍵與照顧對象選單。
3. **P1 觸碰與動作**：貓狗都能使用跳台吊球；平地流暢、上下樓真正踩階，互動時維持插畫外觀。
4. **P1 自助檢查**：程式內一鍵短測／長測、停止、進度、完成通知與持久報告。

不以新增第四層、新角色、雲端 AI、即時 AI 補幀或整個引擎重寫作為本版前提。

## 3. 共用互動規則：先回應，接觸後才生效

所有照顧統一經過「收到操作 → 可執行／等待並說明原因 → 前往／準備 → 實際接觸 → 完成」，另有拒絕、中斷與失敗。每個請求綁定實際碰到的角色 ID 與物件 ID，不再依賴全域照顧對象。

- 可見物件在操作後立即給小幅高亮、動作或簡短提示；若忙碌、飽了、走不到或正在下樓，當場看得到原因。動物以姿態／小圖示表達，必要文字放在物件提示；不把動物變成長篇對話框。
- 接受請求不等於已完成。進食在每一口扣食物並降低飢餓；梳理、撫摸在有效接觸段結束後結算。取消或失敗不能獲得完整收益。
- 佇列有長度與期限；新目標搬走、收起、被佔用或顯示器消失時可安全結束。已進入樓梯先完成安全落腳，不能突然切動作停在半空。
- 拖曳角色、佈置、全螢幕隱藏、暫停與恢復沿用原安全恢復保護；停止不等於成功，清理不抹掉尚未完成的逃離／落地。
- 同一接觸只結算一次；重複事件、恢復與重啟不能重複扣糧或發獎勵。親密度有冷卻與上限，游標停著不會無限增加。

## 4. 餵食：房間裡真的有食物

### 貓狗的食盆

放下食盆 → 點盆補充飼料 → 看見剩餘量 → 貓狗餓了自行前往 → 逐口消耗 → 吃飽離開，空盆等使用者補充。

- 食盆支援貓用／犬用飼料；若提供共用配方，須明確標示可食角色。點選的是食物種類，不是全域照顧對象。
- 點盆出現小型補充卡，首版提供「加一份」「補滿」。一般畫面只保留空／少／半／滿的插畫，靠近才顯示份量，避免桌面掛滿數字。
- 同一食盆一次一位角色使用；另一位等待或尋找別盆。食物份量不能負數，也不能被兩位同時吃掉同一份。
- 每口有低頭／嘴部接觸、食物減少與飢餓降低；只補糧不會隔空把角色餵飽。使用者移走食盆時停止後續進食，已吃下的份量保持結算。
- 滿盆初始平衡目標約能支持一位角色 3–4 小時一般陪伴，再依實測調整；這是遊戲節奏目標，不是現實飼養建議或保證時長。
- 關閉程式不追扣食物、不額外懲罰使用者；重開保留剩餘量，避免每次回來都空盆。離線需求沿用溫和陪伴規則。
- 少量／空盆只作不打擾的提示；不增加金幣、付費商店、烹飪排程或強迫登入。

### 女孩的餐桌

放餐桌與可用座位 → 點桌上的餐盤位置選料理 → 料理出現在桌上 → 女孩餓了自行坐下用餐 → 餐盤逐步變空。

- 首批五種主題：漢堡套餐、炸雞套餐、火鍋、拉麵、雞排；涵蓋使用者提到的麥當勞／肯德基餐點方向，以原創同風格餐點插畫呈現。
- 漢堡／雞排用手拿，拉麵／火鍋用對應餐具，不只更換圖示。份量與吃完時間可不同，但不建立複雜營養系統。
- 新增餐桌提供一鍵搭配座位；沿用舊桌椅 ID，缺椅或座位不可到達時直接提示並提供「補上座椅」，避免放了料理仍無反應。
- 料理附著餐桌插槽，不占一個新家具名額，也不掉在桌後。移動餐桌時一起移動；跨樓層、存檔和重啟都保留相同附著關係。
- 首版用餐限定餐桌；女孩不吃寵物飼料，貓狗不搶人類料理。沒有餐桌或沒有料理時不憑空減少飢餓，顯示缺少什麼。
- 吃剩食物保留；換菜需清楚顯示會收起舊餐點，食物不會在背景自動替換。首版不加入腐敗倒數。

## 5. 其他直接互動與控制台簡化

|---|---|---|

角色照顧右鍵選單全部移除，控制台的「照顧對象」及手動餵食／玩球／梳理／睡覺按鈕一併取消。角色卡保留名字、狀態、回憶與個別設定；改名、重設位置、習慣管理須明確綁定該張卡，不能殘留隱藏全域選擇。

家具補糧、點餐、收起使用左鍵物件卡；擺放位置仍由佈置模式處理。系統托盤保留顯示、設定與結束程式功能，不放照顧指令。若 spacedesk 傳回觸控事件，提供點頭部的一次撫摸作為替代，是否支援須以實機確認。

正常模式只讓食盆、餐盤、梳子與吊球等可操作區域接收點擊；家具透明外框繼續穿透。不可為每口食物、手勢或粒子再建立獨立原生視窗；小螢幕的操作卡維持可讀尺寸，不跟角色一起縮得過小。

## 6. 貓跳台吊球：成為真的附掛玩具

- 吊球具有獨立玩具 ID、吊點、繩長、角度、角速度與接觸區，跟隨家具移動；圖像位置與物理位置採同一座標來源。
- 使用者可直接撥動／拖一下球後放開；球有有限擺動、阻尼與繩長限制。角色撥到才施加反作用，不先播放命中效果再補判定。
- 貓在適合的平台或地面撥球；狗在地面抬前爪／鼻碰，不能因開放吊球而獲得攀爬貓跳台的能力。
- 太高、太遠或被佔用時提供回饋，角色可等候或改做其他事；預設吊球要有貓狗可達的低位，不能所有狗案例一律「碰不到」。
- 角色、玩具與家具按同一場景縮放；主螢幕、S20、小屋三層及偏移家具都要覆蓋。球移動時追蹤目標有界更新，保留真正停滯的逾時判定。
- 接觸時繼續使用插畫角色，逐步替換現行貓爪互動切回幾何外觀的做法。

## 7. 流暢動畫與真正踩階

### 更新節奏

採單一場景時鐘，需求／決策維持低頻，移動與玩具採固定且有補算上限的模擬步進，顯示在繪圖時讀取前後狀態做插值。繪圖不能再次增加飢餓、推進導航或扣食物；停頓後不能無上限補算。

保留原生透明視窗架構，先處理位置殘餘小數、只在內容改變時移動視窗、可重用的接觸資料與素材快取。拖曳、跨螢幕、重設位置、落地與暫停恢復須重設插值歷史，避免穿牆與拖尾。多螢幕使用各自實際 DPI，不能拿 WPF Left／Top 直接當世界座標。

Microsoft 說明 Rendering 回呼可逐繪圖更新，但頻率依負載而變；改動 layout 還可能觸發額外排版。因此它是實作工具，不是保證 60 FPS 的開關：[WPF 逐幀繪圖](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/graphics-multimedia/how-to-render-on-a-per-frame-interval-using-compositiontarget)。

### 腳與階梯

每一步分為「支撐腳留在踏面 → 另一腳抬起跨階 → 腳掌落在下一踏面 → 重心轉移」。上樓與下樓分開；女孩雙足、貓狗四足各有自己的時序。步態依真實行進距離與落腳事件同步，不再只沿斜線移動普通走路貼圖。

導航仍保留入口／出口、通行預約與安全取消；身體支撐、足部目標與畫面踏面用同一份幾何資料。不能只新增上下起伏，或讓資料裡的虛擬腳點正確、圖片裡的腳仍滑動。

目前每層樓梯約升 352 DIP、水平 240 DIP、16 階，約 56 度。真正踏步需先驗證踏面深度、女孩淨空與四足可達性：寬螢幕原型評估較長梯段；S20 比較固定緊湊梯段／折返平台。這是待原型決定的版型，不先承諾增加自由樓梯編輯，也不靠縮小整個小屋解決。

### 美術交付方式

先做女孩「平地走 → 上樓 → 下樓」一組完整片段，驗證插畫線條、衣物、腳部接觸與停止銜接，再擴至貓狗。素材採經校對的關鍵姿勢＋有限分層：固定畫布、身體基準、左右腳／爪、手、頭、嘴、工具接觸點、落腳事件與根部位移都寫入 manifest。

候選可從 12–16 個關鍵姿勢原型開始，對髮尾、尾巴及局部肢體作平滑動作；畫格數量本身不作驗收。整張角色交叉淡入淡出會出現雙腳／雙眼，不作主要補幀法。AI 中間幀若採用，只離線產生並逐格檢查，不在使用者電腦即時推論。

嘴／手／爪／頭接觸資料同時服務進食、梳理、摸頭和吊球，避免各功能再增加一套不一致的距離常數。

### 驗收目標與量測邊界

- 比較相同機器、DPI、三角色、家具數、1／2／3 層的改前改後場景；平地、上樓、下樓、停步、轉身、追球及照顧各自標記。
- 記錄模擬耗時、Rendering 回呼間隔 p50／p95／p99、超過 50ms 次數、配置量與視窗移動數。依顯示週期 T，候選目標 p95 ≤ 1.5T、p99 ≤ 2T；先取得基線再確定門檻，不能為讓測試通過而掩去正常操作的停頓。
- 支撐期腳／爪接觸漂移以約 2 個顯示像素內作原型目標，配合實際動畫目視；轉向與起停無突跳、跨樓層無穿階、取消仍安全落地。
- 主機回呼、Windows 呈現、spacedesk 傳輸與 S20 實際看到的畫面分開驗證。主機數字不代表手機幀率；不能只拿 GIF 擷取頻率或 dispatcher 延遲宣稱流暢。
- 效能改善優先於更多粒子與裝飾；靜止道具不反覆移動視窗。CPU／配置量與持續記憶體趨勢記錄前後值，不預先宣稱不存在洩漏。

## 8. 進階／診斷：按一次，測完自己交報告

修好展開閃退後，頁內提供「短測 10 分鐘」「長測 2 小時」「停止並保留報告」「查看上次結果」。預設短測，長測由明確選擇啟動，不因小修改或一次失敗自動重跑。

- 測試由獨立且不可變的程式副本執行，使用合成隔離存檔。正式角色、名字、回憶、作品與快捷圖示不進入測試資料；不對真實桌面圖示做測試。
- 顯示目前階段、主要場景已跑時間、預計完成時間、最後更新、三角色狀態與第一個錯誤。10／120 分鐘是主要場景時長，啟動、保存與重啟核對時間另外顯示。
- 同時只執行一項診斷。效能量測期間暫停正式場景，避免兩組桌寵污染結果，結束／停止後恢復。可見畫面測試不得偷偷在完全隱藏視窗下完成並宣稱畫面流暢。
- 控制台可縮小或收進托盤，測試繼續；重新開啟會連回同一 run ID。控制台崩潰不應抹掉 worker 的進度與報告；重新啟動辨識仍在執行或已中斷的作業。
- 停止為合作式取消：保存最後樣本、解除占用、結束自有測試程序，結果為「已停止」。失敗、崩潰、中斷、逾時分開記錄；未跑完不能顯示通過。
- 成功／失敗／停止時本機通知一次，保存摘要與完整報告；首個關鍵錯誤自動留現場並停止。日誌有容量上限，避免長測本身吃滿磁碟。
- 報告含程式版本與雜湊、場景、DPI、實跑時間、接觸與失敗計數、效能摘要；匯出只包含診斷資料，不夾帶真實使用者存檔。

**程式內測試與發行驗證分開命名。** 安裝版不附 SDK，不能單靠按鈕完成建置與單元測試。頁面結果稱「執行中短測／長測」；開發流程的 Standard 仍包含建置、單元、原生檢查與 600 秒短測，Full 才再包含完整長測及其他發行核對。任何重用都需相同程式、設定及場景雜湊。

給自動化的介面提供 run ID、持久狀態、取消與完成事件；Codex 可等候完成事件，或只在預計完成時間安排一次回查。平常進度由程式自己顯示與記錄，不再要求每分鐘讀報告。只有完成事件橋接已實作並驗證時，才宣稱能自動喚醒代理；單純寫出 JSON 並不等於 Codex 會醒來。

## 9. 資料與架構邊界

在原 WPF／Core 專案中分出小型共用服務：InteractionSession、FoodContainer／MealServing、AttachedToy、ContactAnchors／StairGait、SceneClock、DiagnosticRunCoordinator。名稱為設計概念，尚非已存在類別。

- 食物以家具 GUID + serving ID 保存種類、總量、剩餘量與附著位置；扣糧與角色飢餓更新在同一已提交狀態保存，避免重啟後重複吃或食物憑空增加。
- 報酬、需求、播放動畫與導航完成分開，接觸事件決定成果。渲染物件不直接寫養成資料。
- 本版預計 schema 7 → 8，實作時驗證所有舊版遷移。舊食盆保留 ID／位置，初始為空並提示第一次補充；不無故生成或扣掉食物。
- 保存角色、家具、樓層、歷史與偏好。刪除食盆／餐桌時清理對應食物與預約；不重用 transient occupancy、過期互動或梳子抓取狀態。
- 舊版拒讀較新存檔；安裝先備份，再提供程式＋對應資料一起回復的入口。

## 11. 必須覆蓋的驗收場景

1. 三角色各自從直接操作到可見回應；飽、累、冷卻、被抱起、佈置、隱藏、家具佔用、走樓梯與目標被移走，均有正確結果且不誤發獎勵。
2. 空盆不吃；補糧後自主吃；雙角色搶同盆；最後一口；吃到一半移盆／取消／退出／重啟；保存失敗回復後不重複扣糧。
3. 女孩五種料理、缺餐桌／缺座位、跨樓層用餐、吃剩換菜、餐桌拖曳與重啟；嘴／手／餐具接觸正確。
4. 只路過頭部、不動游標、有效撫摸、拖角色、梳子越界與 Escape；頭部被其他視窗遮住時不誤觸，觸控替代只在實機支持時驗收。
5. 貓／狗吊球地面或平台接觸、碰不到、佔用、家具縮放與移動、球被抓住；球的擺動需來自真正接觸。
6. 女孩雙足與貓狗四足的平地／上下樓／起停／轉身；樓梯中途取消、食盆在樓梯旁、排隊與安全恢復；動作期間不切回粗糙幾何角色。
7. 診斷展開、啟動、縮小、停止、worker 崩潰、控制台重開、錯誤報告、空間不足；結果不漏記、不誤標通過、不影響正式資料。
8. 主螢幕 125% 與 spacedesk 175%、1／2／3 樓、三角色＋常用家具；S20 實體斷接、旋轉、休眠恢復單獨實測，沒有操作硬體便保持未驗證。
