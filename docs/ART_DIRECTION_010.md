# Desktop Life 0.10 美術方向與素材契約

更新日期：2026-10-02。使用者提供的女孩、邊牧犬、橘貓三張角色設定圖，是本輪的視覺方向參考；設定圖本身不作為桌寵貼圖或主控台背景。

## 想做出的感覺

以溫暖的日系插畫陪伴感為中心：柔和光線、細緻毛髮或髮絲、大而有神的眼睛、奶油色衣物與粉色小配件。可愛來自姿態、表情和比例；不靠增加滿畫面的特效。角色在一般桌面尺寸仍需容易辨識，UI 讓角色先被看見。

| 角色 | 必須保留的視覺特徵 | 動作個性 |
|---|---|---|
| 邊牧犬 | 黑白長毛、額頭到鼻口的白色線條、白胸與白爪、柔軟垂耳、粉色項圈與金色吊牌 | 活潑、好奇、搖尾、坐下等待；睡覺時柔軟地趴下 |
| 栗子／橘貓 | 橘色虎斑、奶油白鼻口與胸腹、金色眼睛、紅色項圈與鈴鐺、蓬鬆尾巴 | 輕盈探索、理毛、蜷睡、耳尾回應；維持貓科行為 |
| 女孩 | 栗棕長髮、花朵髮飾與粉色蝴蝶結、奶油白開襟衫、粉灰格裙、柔軟居家鞋 | 用餐、整理頭髮、畫畫與閱讀；使用人類姿態 |

## UI 規則

主控台用奶油紙色底、可可色文字、淡粉與淡紫分區，保留足夠留白。圓角卡片與短標題將「選擇角色 → 照顧 → 回憶／房間」放在前面；顯示、聲音、存檔與診斷折疊收起。常用的顯示／隱藏／重設／暫停操作留在底部。

## 0.10 素材管線

本輪先採用透明 PNG 姿態圖集，讓既有 WPF 程式能實際顯示插畫角色。每張基本圖集概念上分成上、下兩排各 4 個姿態，共 8 個獨立輪廓；生成圖的留白不是精密像素格線，`CompanionSpriteVisual` 依 alpha 的連通區域擷取真正的姿態邊界，再依上排由左到右、下排由左到右排序。不能直接把整張圖集放在角色視窗，也不能在每幀重新讀檔或裁切配置新圖片。

- 基本資源：`Assets/Companions/border-collie-v1.png`、`orange-cat-v1.png`、`girl-v1.png`；女孩另有 `girl-activities-v1.png`。四張均為 1536 × 1024，每張 8 姿態。角色縮圖使用相同資源中的單一姿態，不重複打包整套圖片。來源、雜湊與連通區域資料記錄在同目錄的 `SOURCES.md`。
- 透明背景需是真實 alpha。細毛邊避免白框、黑邊與殘留背景；卡片陰影不寫入桌寵貼圖。
- 各格的身體比例、配件、毛色與服裝保持一致；睡眠、坐姿與活動姿態各自有合適的腳底／身體支撐位置。
- 圖片按角色載入一次，擷取後凍結並快取 WPF 位圖，再供角色與主控台預覽共用。所有姿態使用同一縮放率與 `y = 144` 支撐基準；輕微呼吸以支撐基準為中心縮放，不將整個角色上下浮動。
- 行為、重力、導航與存檔仍由既有邏輯處理；美術替換不能改變角色身份或清除歷史。
- 桌寵需要透明邊界命中檢查。圖集外框、透明留白、縮圖以及陰影不能吞掉桌面滑鼠操作。
- 缺少或失效的素材使用可見的保底外觀，不讓角色無法啟動；保底不算完成插畫品質驗收。

0.10 的圖集是插畫外觀與有限姿態的第一階段。呼吸、鏡像轉向與兩幀走動可改善日常感，但整張圖片移動不代表完成四足骨架、人類手部 IK、毛髮模擬或家具精密接觸。貓需要精確前爪追蹤玩具時保留原有程序式四足外觀；這個情境會與插畫外觀有差異。家具、球與部分活動道具仍使用原有向量，尚未完成全專案美術替換。

女孩基本圖集包含坐下、睡眠、用餐、畫畫等有限姿態，活動圖集提供電腦、閱讀、積木、整理頭髮、寫字、休息與伸展的可辨識畫面。這些道具繪入各活動姿態，尚未與家具做精確手部接觸、跨視窗拿取／放回或獨立積木物理。活動圖集缺失時通用坐姿不能算完成這些活動的美術驗收；導入驗證以更新文件與當次摘要為準。完整分層、更多方向與接觸關鍵幀按後續里程碑導入；目前沒有使用 Live2D、Spine 或新的遊戲引擎。

## 進一步分層

下一輪可分頭部、身體、遠／近側四肢、耳朵、尾巴、眼睛／眼皮、嘴與配件。女孩使用獨立的人類骨架與手部素材，不能套用貓或犬的四足骨架。家具分前景遮擋／承托面／背景，逐件替換為相同材質的插畫資源。

每個姿態需有根位置、pivot、支撐點、命中區與有效插值範圍。保持既有邏輯身高和支撐基準；圖片解析度不能直接決定物理尺寸。這部分是後續規劃，不是目前圖集的功能。

## 驗收

1. 三個角色在 100%、125%、150%、200% DPI 仍清楚；正面、坐下、走動、用餐與睡眠的輪廓易辨識。
2. 透明邊界、拖曳、落地、朝向、影子、家具前後遮擋逐項檢查；不以一張概念圖代替動態檢查。
3. 相同場景量測單角色、雙角色、家具與作品多物件情境的幀時間、CPU、記憶體與載入時間，並與 0.9 基準比較。
4. 素材缺失、切換角色、重啟與舊存檔載入都可正常完成；替換外觀不能複製另一角色的習慣。
5. 將「素材已導入」「自動檢查通過」「真實時間長測完成」「人工美術接受」分別記錄；未完成的項目保持待驗收。
