# Desktop Life 升級路線與完成邊界

更新日期：2026-10-08。由現有 0.9 工作目錄繼續升級，保留既有修改、角色資料與本機陪伴定位。優先順序是「邊牧犬與插畫美術 → 卡頓與可靠性 → 新功能與體驗」；階段驗證通過後直接推進，沒有足夠證據時不把規劃寫成已完成。

## 0.10：看得到、用得到的新角色與美術基礎

| 工作 | 完成邊界 |
|---|---|
| 新增邊牧犬 | 可選擇、顯示、照顧、拖曳與保存；犬類動作與能力分開定義，不能當作改色橘貓 |
| 三角色插畫外觀 | 依提供的三張設定圖導入透明姿態素材與 alpha 區域擷取／快取 renderer；一般桌面尺寸清楚，保留既有物理與命中 |
| 主控台改造 | 奶油紙色、粉紫角色卡片、明確照顧區；設定與診斷折疊收起，常用操作容易找到 |
| 明顯卡頓修復 | 先確認繪圖、UI 更新、存檔與多視窗配置熱點，修復可重現的問題並留下對照 |
| 相容升級 | v2/v3/v4/v5 完整歷史遷移至 v6，保護第三角色不被舊版忽略；安裝前正常退出並備份，使用升級前備份可回復舊版 |

本輪已改造主控台樣式與排列，保留原有具名控制項與操作回呼。角色、renderer 與效能修正由同一版整合交付；實際完成清單與量測結果應寫入本版更新文件，不能僅以這份路線圖判定。

本輪角色素材是有限姿態圖集。貓精確前爪玩具接觸仍保留原程序式骨架外觀，家具與部分道具仍使用舊向量；完整分層骨架、各方向連續動畫、精細家具接觸與全家具插畫仍待後續完成。三個角色插畫已出現，不等於整個專案美術已全面完成。

第三角色的新增欄位需要 schema v6 作為降版保護。0.9 不認識第三角色，即使主角色與顯示選項保持舊值，仍可能接受 v5 後丟掉第三角色；因此不能只增加 optional 欄位卻維持 v5。升級測試需涵蓋兩個舊角色完整歷史、第三角色獨立歷史、原檔備份、未知版本拒絕，以及匯入／匯出邊界。要回到舊版，使用安裝前的完整備份。

驗收至少包含完整建置與適用的核心測試、真實 WPF 啟動和角色互動、舊資料載入／保存／重啟、單／多角色顯示、素材透明邊界、家具與作品場景。短測與確定性步進只證明相應功能，不能宣稱兩小時穩定性。

## 0.10.1：可靠性與效能收斂

2026-10-03 已完成本階段安裝：439項測試、兩小時三角色Full及正式資料核對通過，結果見 `UPDATE_0101.md`。以下驗收範圍已落實；混合DPI、真實螢幕拔插與硬體休眠留待實機驗收。

1. 建立可重複基準：相同機器、DPI、角色、家具數、作品數、視窗層級與執行時間；記錄 UI 派送延遲 P50／P95、CPU、工作集／配置趨勢、存檔耗時與崩潰。畫面幀時間與 FPS 若要量測，另設實際渲染採樣。
2. 依實際證據排序：阻止啟動／存檔或破壞資料為 P0；經常卡住、點擊失效、角色穿越／失蹤為 P1；偶發動畫與排版瑕疵為 P2。每個問題附重現步驟、修正位置與驗證結果。
3. 去除每幀重建的圖片、字串、繪圖資源與非必要 UI 更新；監控與診斷降頻或按需更新。角色隱藏、暫停、安靜與最小化情境分別檢查。
4. 跑真實十分鐘三角色壓力測試，再完成至少兩小時原生 WPF 長測；檢查回應、存檔、記憶體走勢、視窗退出與重啟。雙角色前後基準比較維持相同場景，不與三角色驗收混為同一數據。
5. 清楚交付基準與修正版差異。沒有量測到的卡頓原因列為待查；沒有跑完的長測列為待驗收。

效能目標先以當前機器的 0.10.0 不可變基準設定；既有 0.9 比較保留為歷史證據，避免把任意 CPU 百分比或一次峰值當成通用承諾。若新素材增加一次性載入記憶體但降低持續配置，要同時呈現兩項結果。穩定性里程碑通過後再擴大新功能。

## 0.11：動畫、角色比例、家具與生活空間

2026-10-08 已完成 0.11 發行驗證：611 項測試、短測與兩小時長測及重啟通過，並已完成正式安裝與原生資料核對，見 INSTALLATION_011.md。前三項方向已接受；空間方案依使用者要求採用固定 1／2／3 層小屋與通用樓梯，最多三層，不提供自由編輯樓板。詳細實作與驗收邊界見 [DESIGN_011.md](DESIGN_011.md) 與 [UPDATE_011.md](UPDATE_011.md)。

已接入三角色 8 幀走路與 4 幀坐下／起身、256／80／104 DIP 相對比例、19 種插畫家具、跨樓層支撐與預約、schema 7 相容存檔及 spacedesk 混合 DPI 修正。本次跨 minor 發行已有同來源 Full PASS；安裝與封裝結果以當次紀錄為準。後續 0.11.x 小更新採 Standard 短測，0.11 → 0.12 等跨 minor 才安排長測，明示停止優先。實體手機拔插／旋轉／休眠另列待驗證。

以下原有日常體驗路線仍保留，首次使用、回憶管理和多螢幕不搶占本版四項核心，可依驗收情況移至後續小版本。

| 項目 | 使用者得到什麼 | 驗收方向 |
|---|---|---|
| 首次啟動與角色選擇 | 清楚選擇朋友、大小、活動螢幕與安靜程度 | 無需閱讀診斷，能完成首次使用並知道如何退出 |
| 各角色一致的命名與照顧 | 切換對象時名字、狀態、回憶、音效一致 | 每項操作作用在明示對象，重啟仍保留 |
| 多螢幕與 DPI | 換螢幕、縮放、休眠恢復後不失蹤 | 混合 DPI、拔插螢幕、螢幕邊界與位置恢復實測 |
| 家具插畫素材 | 房間與角色同一視覺風格 | 逐件驗證尺寸、碰撞、遮擋與前後層級 |
| 更多姿態與方向 | 轉身、走動、坐下、互動更連續 | 增加方向和接觸關鍵幀，避免拖曳整張圖片假裝接觸 |
| 輕量回憶與作品管理 | 看得懂個性變化，容易保留或收起作品 | 有容量上限、查找與清除說明，不強迫離線照顧 |

這些項目目前是規劃，尚未以完整功能交付。每個子項可拆成小版本，先完成一段可驗收的使用流程，再增加下一段。

## 0.11 後續小版本：先改善已看見的細節

本輪固定小屋預覽已確認兩層／三層可分散家具，但一層放齊全部家具仍擁擠；目前 S20 三層配置約縮至 53%，小道具會偏小。後續以這些實際限制排序，不預先增加第四層或新角色。

| 優先順序 | 下一個可驗收項目 | 完成證據 |
|---|---|---|
| P1：實機連線恢復 | spacedesk S20 實體拔插、旋轉、休眠／喚醒後保持可見與安全支撐 | 各事件的實機前後位置、DPI、恢復及資料保存記錄；注入清單不能替代 |
| P2：家具組合 | 電腦、畫本附著於書桌；桌面支撐、前後遮擋與跨樓層一起保存 | 放置／拖曳／整理／重啟後都在同一家具表面，不改成無碰撞裝飾 |
| P2：小屋美術 | 木樓板、樓梯踏面與扶手增加與家具相符的插畫細節 | 一至三層與兩個工作區的清晰度、alpha 點擊及支撐一致 |
| P2：更多連續演出 | 優先睡下／醒來及常用家具活動，延續已完成的走路與坐下／起身 | 實際 renderer 動態檢視與家具接觸回歸；不以畫格張數代替觀感 |
| P2：小螢幕閱讀性 | 在保留固定一至三層的前提下，讓樓層選擇清楚顯示尺寸取捨 | 使用者能預期兩層較大、三層較分散；角色與家具仍共同縮放 |

以上是後續規劃，沒有在本次 0.11 驗證期間擴充程式範圍。

## 0.12 以後：按證據擴充

待前述可靠性與日常體驗收斂後，再評估更完整的分層骨架、角色共同演出、更多個性與家具活動、可驗證的素材包。新引擎、雲端服務、LLM 或深度系統重寫都不是目前必要條件；加入前必須能說明具體收益、成本與相容方案。

## 每版固定交付

- 一份短更新說明：已完成、實際驗證、已知限制、下一步。
- 可追溯的驗證摘要與量測資料，區分自動檢查、真實視窗、真實時間長測與人工美術接受。
- 安裝包、版本辨識、資料備份與回復路徑；禁止用新版本覆蓋唯一存檔。
- 有優先級的問題清單；不因功能數量增加就宣布完成。

0.11 螢幕小屋已完成驗證與安全安裝；0.10／0.10.1 留作已完成階段及歷史依據。整體升級是持續路線，這份文件不代表所有未來版本已完成。
